# Contributing to Dock Pet

Thanks for taking a look. This is a small, opinionated project, and a few of its
constraints are not obvious from the code. Reading this first will save you from
writing something that has to be rejected.

## Before you write code

Read these, in order:

1. This file.
2. [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md) — how to build, test, and run.
3. [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — the state flow and invariants.
4. [`DesktopMascot.md`](DesktopMascot.md) — the project ledger. It records every
   decision and, more usefully, the things that were tried and did not work. If
   you are about to change scope, architecture, art, or product behavior, read
   it in full. Several plausible-looking ideas are already in there with
   evidence for why they were abandoned.

For anything larger than a bug fix, **open an issue first**. Dock Pet has a
narrow product definition and a maintainer who has said no to a lot of
reasonable-sounding features.

## Hard invariants

These are not style preferences. A pull request that breaks one will be closed.

**Platform.** Dock Pet is a native macOS 14.4+ SwiftUI/AppKit accessory app. Not
Electron, not a browser overlay. No Dock injection and no private APIs.

**Privacy.** The app never reads or stores prompts, transcripts, source code,
tool arguments, tool output, repository paths, tokens, or screen content. Agent
integrations accept coarse lifecycle events and nothing else. Session
identifiers are hashed before they leave the hook helper. No network access, no
telemetry, no accounts. This boundary is the product; do not widen it for
convenience.

**Character identity is frozen.** `art/production/mascot-base-chibi-40pt-at2x-80px-final.png`
is the mascot. Do not redraw it, and do not revive the rejected tall variants.
New poses must fit the existing atlas contract.

**Art pipeline is deterministic.** Sprites are generated by the scripts in
`tools/`, not hand-edited. `art/animation/atlas-contract.json` is the
machine-readable geometry and timing contract. Sprites render with
nearest-neighbor interpolation and binary alpha, within the frozen 12-color
palette. Run `python3 tools/validate_animation_atlas.py` after any art change.

> One documented exception: `mascot-atlas-codex@2x.png` may use the three
> additional orange shades declared in `tools/author_codex_fashion_atlas.py`.
> The validator reporting three off-palette colors for that one file is
> expected, not a regression.

**One source of truth for behavior.** `MascotVisibleState` decides what the pet
is doing. Anything that wants to change the animation goes through
`MascotStateReducer`. Never set an atlas row directly, and never write a
provider-specific ordering — the per-provider reduction is the same priority
ladder applied to a narrower list, on purpose.

**The app must always be escapable.** A menu bar item for summon, dismiss,
pause, and quit is mandatory. Quitting must never depend on an animation
finishing.

**Never edit the user's agent configuration.** Dock Pet prints a hook snippet
and the user pastes it. This is deliberate.

**The Xcode project is generated.** `project.yml` is the source of truth. Change
it and run `xcodegen generate`; do not make a durable edit to
`DesktopMascot.xcodeproj` alone. Commit the regenerated project with the
`project.yml` change.

## Development workflow

Set up:

```bash
git clone https://github.com/Mr-Shine09/desktop-mascot.git
cd desktop-mascot
```

Validate the art contract:

```bash
python3 tools/validate_animation_atlas.py --contract-only
python3 tools/validate_animation_atlas.py --atlas art/animation/mascot-atlas@2x.png
```

Run the test suite, from `Packages/DesktopMascotKit`:

```bash
swift test
```

The baseline is 198 passing Swift Testing tests. A higher count is fine; a lower
count needs investigation.

Build the app:

```bash
xcodebuild \
  -project DesktopMascot.xcodeproj \
  -scheme DesktopMascot \
  -configuration Debug \
  -derivedDataPath /private/tmp/DockPetDD-$(git branch --show-current | tr / -) \
  CODE_SIGNING_ALLOWED=NO \
  build
```

**Give every branch and worktree its own `-derivedDataPath`.** It is shared
mutable state, not scratch space. Two builds into the same path means the last
one wins, silently, and you end up testing someone else's branch. This has
already cost a debugging session — four features looked broken because they
simply were not in the bundle that got launched.

## Testing expectations

Match the tests to the change:

| Change | What to run |
| --- | --- |
| Core / event logic | Package tests plus new fixtures |
| Window behavior | Package tests, an unsigned build, and the relevant manual checks |
| Atlas / art | Contract, frame-row, and atlas validation; QA render; crop test; build |
| Project / resources | Regenerate the Xcode project and inspect the bundled resources |

Fixtures that involve time must use an injected instant. One fixture family
reduces against the 23:00–06:00 sleep window, and a test that reads the real
`Date()` will pass all day and fail all evening.

## Pull requests

- Branch from `main`. Short-lived branches, named `agent/<topic>` or
  `fix/<topic>`.
- One logical change per pull request.
- Run `git diff --check` before committing.
- Commit generated output — the Xcode project, the atlases — in the same commit
  as the source change that produced it.
- Fill in the pull request template honestly, including the "not verified"
  parts. An accurate list of what you did *not* test is more useful than a
  confident claim that turns out to be wrong.
- Pull requests are squash-merged.

### On evidence

This project has a documented habit of distrusting claims that were not
verified against the committed file. If your description says a document was
updated, check with `git show HEAD:<file> | grep` rather than trusting that your
edit applied — a string replacement whose target does not match fails silently,
and that has produced false claims here before.

A build succeeding is not evidence that a feature works.

## Reporting bugs

Use the issue templates. Include your macOS version, whether you built with
`install_app.sh` or `xcodebuild`, which agent and provider you were using, and
what the menu bar's `Event socket:` and `Reduced state:` lines said at the time.

Do not paste prompt or transcript content into an issue. Dock Pet never sees it,
and neither should the issue tracker.

## Contributing art

Read [`docs/ASSET_PIPELINE.md`](docs/ASSET_PIPELINE.md) before drawing anything.
Art submitted through a pull request is licensed under
[`art/LICENSE.md`](art/LICENSE.md), which is more restrictive than the code
license — the mascot depicts a real person. If you would rather not license work
on those terms, open an issue describing the change instead.
